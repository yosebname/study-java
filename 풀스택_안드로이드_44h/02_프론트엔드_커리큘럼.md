## 📊 2026년 7월 기준 스택 판단

| 항목 | 결론 | 근거 |
|------|------|------|
| **언어** | JavaScript → **TypeScript 5.9+ (strict)** | 채용 공고 사실상 전부 TS 필수. 2026 프레임워크들이 **TS를 기본값(baseline)** 으로 전제 |
| **라이브러리** | **React 19** | 국내외 수요·생태계 1위. 신입은 **React 하나만 깊게** 파는 게 유리 |
| **메타 프레임워크** | **Next.js 16 (App Router)** | 서버 컴포넌트(RSC)가 2026 프론트의 기본 축. Next 16 · Astro 6 · SvelteKit 모두 서버 컴포넌트 일급 지원 |
| **빌드** | **Vite 7** (SPA/학습용) + Next(프로덕션 웹) | Vite는 ESM 네이티브. CRA는 완전히 사망 |
| **스타일** | **Tailwind CSS v4** | CSS-first 설정(`@import "tailwindcss"`), 설정 파일 없이 시작. OKLCH 색상·네이티브 캐스케이드 레이어 |
| **서버 상태** | **TanStack Query v5** | Redux로 서버 데이터 관리하던 시대 종료 |
| **클라이언트 상태** | **Zustand** (+ Context) | Zustand + TanStack Query 조합이 복잡한 Redux 아키텍처를 대체 |
| **폼/검증** | React Hook Form + **Zod** | Zod 스키마는 타입까지 뽑아줌 |
| **UI 킷** | **shadcn/ui** | 복붙형 컴포넌트. 코드가 내 저장소에 남아 학습에 유리 |
| **테스트** | Vitest + Testing Library + **Playwright** | |

### 2026년의 진짜 변화 3가지 — 이건 꼭 이해하고 가세요

1. **React Compiler** — 빌드 타임에 리렌더를 자동 최적화합니다. **`useMemo`/`useCallback` 수동 떡칠 시대는 끝났습니다.** 초보자에게 오히려 좋은 소식이니, 옛날 강의에서 memo를 도배하라고 하면 그 부분은 무시하세요. (단, **왜 리렌더가 일어나는지**는 여전히 알아야 합니다.)
2. **서버 우선(Server-first)** — RSC는 기본값을 뒤집었습니다. 모든 JS를 브라우저로 보내는 대신 **서버에서 렌더하고 필요한 조각만** 보냅니다. `'use client'`를 언제 붙이는지가 핵심 감각.
3. **AI 보조 워크플로** — 컴포넌트 한 개쯤은 AI가 즉시 뽑아냅니다. 그래서 **"만들 줄 아는 사람"의 가치가 "설명하고 고칠 줄 아는 사람"으로 이동**했습니다. `05_코드작성법.md` 6장을 반드시 읽으세요.

## 🎓 A~Z 단계별 로드맵

### A단계 — 환경 세팅 (1주)
- **VS Code** + **Node.js LTS** + Chrome 개발자도구(F12) + Git
- 확장: Prettier, ESLint, Tailwind CSS IntelliSense, Error Lens
- 🛠 `index.html` 만들어 브라우저에 띄우기

### B단계 — HTML (1주)
- 시맨틱 태그(`header/nav/main/section/article/footer`), 폼, 이미지, 링크, 테이블
- **접근성 기초**: `alt`, `label`, 헤딩 순서
- 🛠 자기소개 페이지를 시맨틱하게 마크업

### C단계 — CSS 기초 (1~2주)
- 선택자, 박스모델, 단위(px/rem/%/vw), `display`, `position`
- 🛠 명함 카드 UI

### D단계 — 레이아웃 (2~3주)
- **Flexbox** (실무 사용 빈도 1위 — 완벽히)
- **Grid** (2차원 레이아웃)
- 🛠 네비게이션 바 + 카드 3열 그리드

### E단계 — 반응형 (3주)
- 미디어 쿼리, 모바일 퍼스트, 가변 이미지, `clamp()`
- 🛠 PC/태블릿/모바일에서 안 깨지는 랜딩 페이지

> 💡 여기서 만든 반응형 감각이 안드로이드 트랙의 Compose 레이아웃(Row/Column/weight)과 **개념이 거의 같습니다.** 의식적으로 대조하세요.

### F단계 — JavaScript 기초 (4주)
- `let/const`, 자료형, 연산자, 조건/반복, 함수, 배열, 객체
- 🛠 콘솔 계산기, 배열 정렬

### G단계 — 함수·스코프·this (5주)
- 화살표 함수, 콜백, 스코프/클로저, 호이스팅, `this`
- **고차 함수**: `map`/`filter`/`reduce` ← Java Stream과 판박이. 대조 학습!
- 🛠 데이터 배열을 map/filter/reduce로 가공

### H단계 — DOM & 이벤트 (5~6주)
- `querySelector`, 요소 생성/삭제, `classList`
- `addEventListener`, 이벤트 객체, **버블링·위임**
- 🛠 **To-Do 리스트** (순수 JS로) ← 같은 걸 Java 콘솔·Compose로도 만듭니다

### I단계 — 비동기 (7주)
- 콜백 → **Promise** → **async/await**, `fetch`, JSON
- 에러 처리(`try/catch`, 상태코드 분기), **이벤트 루프** 개념
- 🛠 공개 API 호출해서 화면에 렌더링

### J단계 — ES6+ (7~8주)
- 구조분해, 스프레드, 템플릿 리터럴, 모듈(import/export), 옵셔널 체이닝, `??`
- 🛠 코드를 모듈 단위로 분리 재작성

### K단계 — TypeScript 입문 (8~9주)
- 기본 타입, 인터페이스 vs `type`, 유니온, 리터럴 타입, 제네릭 기초

- 🛠 JS로 만든 To-Do를 TS로 전환

### L단계 — TypeScript 심화 (9~10주)
- 함수 타입, 유틸리티 타입(`Partial`/`Pick`/`Omit`/`Record`), 타입 가드, `unknown` vs `any`
- **API 응답 타입 정의** ← 백엔드 트랙의 공통 응답 포맷과 1:1 매칭
- 🛠 백엔드 Swagger 문서를 보고 타입 파일 작성

### M단계 — React 19 입문 (10주)
- **Vite로 React + TS 프로젝트 생성**, JSX, 컴포넌트 분리, 렌더링 흐름
- props, `useState`, 단방향 데이터 흐름, 리스트 렌더링과 `key`
- 🛠 카운터 + 입력폼 + 목록 컴포넌트

### N단계 — Hooks (11주)
- `useEffect`(의존성 배열·클린업), `useRef`, 커스텀 훅
- `useMemo`/`useCallback`은 **개념만** 이해 (React Compiler가 대부분 처리)
- 🛠 API 호출 → 로딩/에러/성공 3상태 처리하는 커스텀 훅 직접 작성

### O단계 — 라우팅 (12주)
- React Router: 페이지 이동, 동적 라우트(`/books/:id`), 중첩 라우트, 보호 라우트
- 🛠 홈/목록/상세 3페이지 SPA

### P단계 — 서버 상태: TanStack Query v5 ⭐ (13주)
- `useQuery` / `useMutation`, 캐싱·무효화(`invalidateQueries`), 낙관적 업데이트
- **"서버 데이터는 상태가 아니라 캐시다"** 라는 사고 전환
- 🛠 목록/상세/등록/수정/삭제를 전부 Query로 (백엔드 API 실호출)

### Q단계 — 클라이언트 상태: Zustand (13~14주)
- 전역 스토어, 셀렉터, Context와의 역할 분담
- 🛠 로그인 상태 · 테마 · 모달 전역 관리

### R단계 — Tailwind CSS v4 (15주)

### S단계 — Next.js 16 App Router ⭐ (16~18주)

- 데이터 페칭, 캐싱·재검증, **Server Actions**, 메타데이터/SEO
