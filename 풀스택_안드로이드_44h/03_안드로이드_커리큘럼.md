# 🟩 안드로이드 커리큘럼 — Kotlin → Jetpack Compose (주 10h)

> 주 44시간 3트랙 플랜의 신규 트랙. 평일 1h × 5 + 몰아치는 날 5h = **주 10h**
> **백엔드가 만든 API를 앱에서 소비하는 것**이 이 트랙의 최종 목표입니다.

## 📊 2026년 7월 기준 스택 판단 — 먼저 이것만 알고 시작하세요

| 항목 | 결론 | 근거 |
|------|------|------|
| **언어** | **Kotlin 2.2+** 단독 | Java로 안드로이드 하는 신규 프로젝트는 없습니다. Kotlin 100% |
| **UI** | **Jetpack Compose** 단독 ⭐ | 신규 프로덕션 앱의 **75% 이상이 Compose 우선**. 구글은 View 시스템 신규 투자를 중단하고 Compose-first 플랫폼 API(윈도우 인셋·예측형 뒤로가기·엣지투엣지)로 전환 |
| **XML 레이아웃** | **배우지 않습니다** ❌ | 옛 강의·책의 절반이 XML입니다. 초보자가 여기서 시간을 가장 많이 낭비합니다. **레거시 코드 읽기용으로만** 나중에 훑으세요 |
| **아키텍처** | **MVVM + UDF** (ViewModel + StateFlow) | 구글 공식 아키텍처 가이드 표준 |
| **DI** | **Hilt** | 안드로이드 표준. 백엔드의 Spring DI와 **개념이 동일** ⭐ |
| **비동기** | **Coroutines + Flow** | 콜백/RxJava는 레거시 |
| **네트워크** | **Retrofit + kotlinx.serialization** (또는 Ktor Client) | |
| **로컬 DB** | **Room** | |
| **디자인** | **Material 3 (Expressive)** | |
| **네비게이션** | Navigation Compose (신규 Navigation 3 흐름 인지) | |
| **빌드** | Gradle **Kotlin DSL** + Version Catalog | 백엔드 트랙과 동일 문법 ⭐ |
| **KMP** | **지금은 배우지 않음** (인지만) | Room·DataStore·ViewModel·Lifecycle·Paging이 `commonMain`에서 쓰이게 되며 KMP가 실전 단계에 진입. 하지만 신입 취업에는 **네이티브 안드로이드 하나를 제대로**가 우선 |

> ⚠️ **초보자가 안드로이드에서 실패하는 이유 1위**: 2019~2022년 강의를 보고 XML + Activity 생명주기 + findViewById에 두 달을 태우는 것.
> **이 플랜은 처음부터 끝까지 Compose만 합니다.** 옛날 자료를 만나면 즉시 닫으세요.

## 🔗 3트랙이 서로를 도와주는 지점 (동기부여용으로 꼭 읽으세요)

| 개념 | 🟦 백엔드 | 🟨 프론트 | 🟩 안드로이드 |
|------|----------|----------|--------------|
| 의존성 주입 | Spring DI (`@Service`) | — | **Hilt** (`@Inject`) ← 개념 동일 |
| 선언형 UI | — | React 컴포넌트 + `useState` | **Composable + `remember`** ← 사고방식 동일 |
| 단방향 데이터 흐름 | — | props 내려주기 / 이벤트 올리기 | **상태 호이스팅** ← 완전히 같은 개념 |
| 서버 상태 캐싱 | — | TanStack Query | Repository + Room 캐시 |
| 비동기 | Virtual Threads | async/await | **Coroutines** |
| 레이아웃 | — | Flexbox (`justify`/`align`) | **Row/Column + weight** ← 거의 동형 |
| 빌드 스크립트 | Gradle Kotlin DSL | — | Gradle Kotlin DSL ← 동일 |
| 타입 안정성 | Java `Optional` | TS `strictNullChecks` | **Kotlin `?` null 안정성** |

> **3트랙은 3배의 부담이 아니라, 같은 개념을 3번 다른 각도로 보는 반복 학습입니다.** 이게 이 플랜이 성립하는 근거입니다.

## 🎓 A~Z 단계별 로드맵

---

### A단계 — 환경 세팅 (1주)
- **Android Studio** 최신 안정판 설치 (JDK는 번들 사용 — 백엔드용 JDK 25와 별개로 두세요)
- SDK Manager, **에뮬레이터 생성**(API 34+), 실기기 USB 디버깅
- 첫 프로젝트: **Empty Activity (Compose)** 템플릿 → 실행
- 🛠 화면에 내 이름 띄우고 실기기에서 확인

> 💡 노트북 사양이 낮으면 에뮬레이터가 지옥입니다. **실기기(안드로이드 폰) 연결을 강력 추천.** 빌드 확인 속도가 3배 차이납니다.

### B단계 — Kotlin 문법 기초 (1~3주)
- `val` / `var`, 기본 타입, 문자열 템플릿(`"$name"`)
- 함수, 기본 인자, 명명 인자, 단일 표현식 함수
- **null 안정성**: `?`, `?.`, `?:`, `!!` (왜 `!!`를 쓰면 안 되는지)
- `if` / `when` (표현식이라는 점이 Java와 다름), `for`, 범위(`1..10`)
- 🛠 Kotlin 문법 100제 (Java로 이미 푼 문제를 Kotlin으로 다시)

#### Java ↔ Kotlin 대조표 (백엔드 트랙과 함께 볼 것)

| 개념 | Java | Kotlin |
|------|------|--------|
| 변수 | `final String s = "a";` | `val s = "a"` |
| null | `Optional<String>` | `String?` |
| DTO | `record Book(String t) {}` | `data class Book(val t: String)` |
| 싱글톤 | `enum` / static | `object Foo { }` |
| 스위치 | `switch` expression | `when` |
| 람다 | `list.stream().map(x -> ...)` | `list.map { it... }` |
| 정적 팩토리 | `static of()` | `companion object` |
| 확장 | 불가 | **확장 함수** `fun String.toSlug()` |

### C단계 — Kotlin 객체지향 & 컬렉션 (3~4주)
- 클래스, 생성자, `data class`, `object`, `companion object`
- 인터페이스, 상속(`open`), **sealed class** (화면 상태 표현에 필수)
- 컬렉션 함수: `map` / `filter` / `first` / `groupBy` (Java Stream과 대조)
- **확장 함수**, 스코프 함수(`let`/`apply`/`run`/`also`)
- 🛠 프로젝트 도메인 모델을 `data class`로 정의 (백엔드 DTO와 필드 일치시키기)

### D단계 — Compose 기본 ⭐ (5~6주)
- `@Composable` 함수, `setContent`, `@Preview` (프리뷰 적극 활용)
- 기본 컴포넌트: `Text` / `Button` / `Image` / `TextField` / `Icon`
- **`Modifier` 체인** (순서가 결과를 바꾼다는 점이 핵심)
- 레이아웃: **`Column` / `Row` / `Box`**, `Arrangement` / `Alignment` / `weight`
- 🛠 프로필 카드 화면 (Flexbox로 만들었던 명함 카드를 Compose로 재현)

### E단계 — 상태 (6~7주)
- `remember`, `mutableStateOf`, `rememberSaveable`
- **리컴포지션**이 언제 일어나는가 (React 리렌더와 동일한 사고)
- **상태 호이스팅**: 상태는 위로, 이벤트는 아래로 → `value` + `onValueChange` 패턴
- 🛠 **Compose To-Do 앱** (JS·Java로 만든 그 To-Do를 세 번째로)

> 🔥 여기서 "React의 props/state와 똑같네"라는 감각이 오면 이 플랜은 절반 성공입니다.

### F단계 — 리스트 & 테마 (7~8주)
- `LazyColumn` / `LazyRow`, `items(key = ...)` (React의 `key`와 동일한 이유)
- **Material 3** 테마: `ColorScheme`, `Typography`, 다크 모드
- `Scaffold` / `TopAppBar` / `BottomBar` / `FAB`
- 🛠 리스트 + 다크모드 대응 화면

### G단계 — 네비게이션 (9주)
- Navigation Compose: `NavHost`, `composable(route)`, 인자 전달
- 목록 → 상세 이동, 뒤로가기, 딥링크 개념
- 🛠 홈 / 목록 / 상세 3화면 앱 (프론트 SPA와 같은 구조)

### H단계 — ViewModel & 아키텍처 ⭐ (10~11주)
- `ViewModel`이 왜 필요한가 (화면 회전에도 상태 유지)
- **`StateFlow` + `collectAsStateWithLifecycle()`**
- **UI State를 `data class` 하나로** 모델링, `sealed interface`로 Loading/Success/Error
- 구글 권장 계층: `UI → ViewModel → Repository → DataSource`
- 🛠 To-Do 앱을 ViewModel 구조로 리팩터링

```kotlin
// UI 상태 모델링의 정석 — 이 형태를 통째로 익히세요
data class BookListUiState(
    val books: List<Book> = emptyList(),
    val isLoading: Boolean = false,
    val error: String? = null,
)
```

### I단계 — 코루틴 & Flow (11~12주)
- `suspend` 함수, `viewModelScope.launch`, 디스패처
- `Flow` 기초, `map`/`filter`, `stateIn`
- 예외 처리(`runCatching`, `try/catch`)
- 🛠 2초 지연 후 더미 데이터를 보여주는 로딩 화면

### J단계 — 네트워크: Retrofit ⭐🔥 (13~14주)
- Retrofit + kotlinx.serialization(또는 Moshi) 설정
- `@GET` / `@POST` / `@Path` / `@Query` / `@Body` / `@Header`
- **에뮬레이터에서 로컬 서버 접근**: `10.0.2.2:8080` (실기기는 PC의 LAN IP)
- `INTERNET` 권한, **cleartext(HTTP) 허용 설정** ← 초보자 최대 함정
- 🛠 **🔥 내가 만든 Spring Boot API를 앱에서 호출해 목록 띄우기** — 이 플랜의 하이라이트

> ⚠️ 여기서 90%가 막힙니다. 체크리스트: ① 서버가 `0.0.0.0`으로 바인딩됐는가 ② 방화벽 ③ `10.0.2.2` ④ `usesCleartextTraffic` ⑤ 서버 CORS는 앱엔 무관(브라우저 정책) ⑥ 응답 JSON 필드명 일치.

### K단계 — Repository 패턴 (14~15주)
- Repository 인터페이스 + 구현체, DTO ↔ 도메인 모델 매핑
- 에러를 `Result` / `sealed`로 감싸 UI까지 전달
- 🛠 네트워크 계층을 Repository로 분리

### L단계 — Room 로컬 DB (15~16주)
- `@Entity` / `@Dao` / `@Database`, `Flow`로 관찰
- **오프라인 우선(offline-first)**: 로컬 캐시 먼저 → 네트워크로 갱신
- 🛠 비행기 모드에서도 목록이 보이는 앱

> 💡 백엔드에서 배운 JPA `@Entity`와 이름·개념이 판박이입니다. 두 번째로 배우는 ORM이라 훨씬 빠릅니다.

### M단계 — Hilt DI (17주)
- `@HiltAndroidApp`, `@AndroidEntryPoint`, `@Module`, `@Provides`, `@Inject`
- Retrofit·Room·Repository를 전부 주입으로 전환
- 🛠 수동 생성 코드를 Hilt로 정리

> 💡 백엔드의 Spring DI를 이미 이해했다면 이 단계는 **하루**면 끝납니다. 3트랙의 복리 효과가 가장 크게 나오는 구간.

### N단계 — 인증 & DataStore (18~19주)
- 로그인 API 호출 → **JWT를 DataStore(Preferences)에 저장**
- OkHttp **Interceptor**로 모든 요청에 `Authorization` 헤더 자동 첨부
- 401 → 로그아웃 처리 / refresh 흐름
- 🛠 웹과 **같은 계정으로** 앱 로그인 성공

### O단계 — 이미지 & UX 마감 (20주)

- 🛠 "빈 목록", "네트워크 없음", "로딩" 3가지 상태 화면을 전부 구현

> 💡 신입 포트폴리오 앱의 90%는 **성공 화면만** 있습니다. 실패·빈 상태를 그린 앱은 즉시 눈에 띕니다.

### P단계 — 권한 & 플랫폼 기능 (21주)

## ✅ 안드로이드 완료 기준

- [ ] Kotlin의 null 안정성·`data class`·확장 함수·스코프 함수를 자연스럽게 쓴다
- [ ] Compose로 화면을 백지에서 그리고, `Modifier` 순서의 의미를 안다
- [ ] 리컴포지션과 **상태 호이스팅**을 설명할 수 있다
- [ ] ViewModel + StateFlow로 UI 상태를 단일 `data class`로 관리한다
- [ ] **내가 만든 Spring Boot API**를 Retrofit으로 호출해 화면에 그린다
- [ ] Room으로 오프라인에서도 동작하는 캐시를 구현했다
- [ ] Hilt로 의존성을 주입하고, Spring DI와 같은 개념임을 설명한다
- [ ] JWT 로그인이 웹과 동일 계정으로 동작한다
- [ ] 로딩·빈 상태·에러 화면이 전부 있다
- [ ] Play Console 내부 테스트로 **실제 설치 가능한 링크**가 있다
