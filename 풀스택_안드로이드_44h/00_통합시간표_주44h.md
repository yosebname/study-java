## 2. 이 플랜의 핵심 전략 — "1 서버, 3 클라이언트"

8개월 뒤 남는 결과물이 **따로 노는 프로젝트 3개**면 실패입니다. 목표는 하나:

```
        [ Spring Boot 4.x REST API + MySQL ]   ← 🟦 백엔드
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   [ Next.js 웹 ]  [ React 관리자 ]  [ Android 앱 ]
      🟨 프론트       🟨 프론트          🟩 안드로이드
```

**하나의 도메인**(예: 독서 기록 / 러닝 트래커 / 중고거래)을 정해서
같은 API를 **웹으로도, 앱으로도** 소비합니다.

> 💡 신입 지원자 100명 중 게시판 CRUD는 90명이 냅니다. **"같은 백엔드를 웹+앱 양쪽에서 붙여봤다"** 는 사람은 5명도 안 됩니다.
> 이게 이 플랜이 44시간을 3트랙으로 쪼개는 유일한 이유입니다. 트랙을 늘리는 게 아니라 **한 프로젝트의 표면적을 넓히는 것**.

**주제는 2주차에 확정하고 8개월간 바꾸지 않습니다.** (주제 갈아엎기 = 진도 리셋)

## 6. 운영 규칙 (이거 안 지키면 44시간이 그냥 증발합니다)

1. **손으로 친다.** 강의를 "보는" 시간은 학습이 아니라 예열입니다. 재생 시간의 **2배**를 손코딩에 씁니다.
2. **매일 커밋.** 3줄이라도. GitHub 잔디는 그 자체로 8개월치 증거입니다.
3. **TIL 3줄.** "① 오늘 배운 것 ② 막혔던 것 ③ 어떻게 뚫었는지". 면접 답변의 원재료입니다.
4. **30분 룰.** 30분 혼자 → 그래도 안 되면 검색/AI. 단, **AI 사용 규칙은 `05_코드작성법.md` 6장을 반드시 먼저 읽으세요.** 잘못 쓰면 8개월 뒤 아무것도 못 짜는 상태가 됩니다.
5. **완벽주의 금지.** 70% 이해하면 넘어갑니다. CS와 프레임워크는 **2회독째 진짜로 이해**됩니다.
6. **버전 고정.** 학습 중 라이브러리 업그레이드 금지.
7. **주제 고정.** "1 서버 3 클라이언트" 도메인은 2주차에 정하고 끝까지 갑니다.
8. **매주 한 번은 반드시 연결.** 몰아치는 날 오후는 **무조건 API ↔ 화면 연동**. 이게 이 플랜의 심장입니다.
9. **수면 6.5시간 사수.** 코드 기억은 자는 동안 굳습니다. 잠을 깎아 만든 19시간은 마이너스입니다.
10. **막힌 에러는 스크린샷 + 해결법을 노션에.** 6개월 뒤 같은 에러를 또 만납니다. 무조건.
